0什么是 audio plugin（音频插件）？

audio plugin（音频插件） 是一个自包含的软件模块，由宿主（host）应用在运行时加载，用于处理或生成音频。宿主 —— 通常是 数字音频工作站（DAW），如 Ableton Live、Logic Pro、Cubase、Pro Tools 或 Reaper —— 掌控着音频硬件、走带（transport）和混音路由图；plugin 被放进这张路由图里只做一件事：滤掉信号的某些频段、压缩它的动态、为它披上混响，或者从 MIDI 合成出音符。

从概念上讲，plugin 是一个对采样流求值的函数。宿主向它传入一小块输入采样以及当前的参数值，plugin 则返回一块输出采样。effect（效果器） 把音频输入映射为音频输出；instrument（乐器） 把 MIDI 输入映射为音频输出。其余的一切 —— 旋钮、电平表、保存的预设 —— 都只是围绕这个核心映射的附属机制。

音轨 / 输入→ EQ→ Compressor→ Saturation→ Delay→ 混音总线

一条典型的 insert（插入） 链：plugin 串联处理信号，每个 plugin 的输出作为下一个的输入。

有两个事实决定了 plugin 的一切写法。其一，它们运行在 实时音频线程（real-timeaudio thread） 上：宿主每隔几毫秒就会调用 plugin 的 process 函数，而它必须在声卡需要下一块 buffer 之前完成，否则听者就会听到爆音。这个回调不能加锁（mutex）、不能分配内存、不能碰文件、也不能阻塞在任意事情上 —— 这是支配一切严肃音频代码的纪律。其二，plugin 必须符合一种 格式（format）：一份二进制与 API 的契约（VST3、AudioUnit、AAX、CLAP……），告诉宿主如何找到它、协商它的 bus、枚举它的参数，并安全地调用它。

1一段简短的历史

plugin 是两股古老世界碰撞的产物：一柜子的外置录音室硬件，和一台快得足以实时模拟它们的通用计算机。

在二十世纪的大部分时间里，信号处理意味着 硬件：无源的 Pultec 均衡器、光电式的LA-2A 压缩器、EMT 板式混响、磁带回声，还有 Moog 模块化合成器 —— 每一台都是接进调音台的实体机箱。数字信号处理最初以昂贵的专用硬件形态进入录音室（Lexicon 224、Publison 和 AMS 的机器、Sony DRE），随后在 1980 年代末以 DSP 卡 系统出现：Digidesign 的 Sound Tools 以及后来的 Pro Tools 依靠安装在电脑内的 Motorola 56000芯片运行效果器。处理仍然发生在定制的硅片上，但路由和用户界面已经搬进了软件。

决定性的突破发生在 1996 年：Steinberg 在 Cubase 中开放了 Virtual StudioTechnology（VST） 接口，并且 —— 关键的是 —— 发布了 SDK，让任何人都能编写运行在宿主 CPU 上的效果器。原生处理、开放的 API，加上越来越快的处理器，把一个小众的硬件市场变成了软件市场。不到十年，调音台、外置机柜和合成器都被重新描绘成了屏幕上的窗口。

1987
Digidesign Sound Tools —— Mac 上首个主流的硬盘录音/编辑系统。效果器运行在专用的 DSP 硬件上；它演化成了 Pro Tools（1991），并带来运行在 56k DSP 卡上的 TDM plugin 总线。
1996
Steinberg VST 1.0 随 Cubase 3.02 发布，并提供免费 SDK。原生的（宿主 CPU 上的）效果器从此对每个人成为可能。首批随附的 plugin —— 包括一个混响和 Espacial —— 奠定了模板。微软的 DirectX plugin（Cakewalk）大约同时出现在 Windows 上。
1999
VST 2.0 增加了 MIDI，从而带来 VST instruments（VSTi）。Native Instruments 的 Reaktor、Propellerhead 的 ReBirth/Reason 时代，以及一波软件合成器接踵而至。Steinberg 的 Neon 是第一款 VSTi。
2002–2005
Apple 在 Mac OS X 中把 Audio Units（AU） 作为 Core Audio 的一部分发布，并与 Logic 和 GarageBand 深度集成。Digidesign 用 RTAS 取代 TDM 的宿主 API，用于原生 Pro Tools 处理。跨平台框架开始出现，一次性覆盖所有这些格式。
2004–2008
JUCE（Julian Storer）成长为跨格式 plugin 领域占主导地位的 C++ 框架。UAD 和 Waves 以精细的硬件仿真起家；卷积混响（Altiverb）和音箱模拟建模成为主流。
2008
VST3 —— 一次推倒重来的重新设计：采样精度的自动化、灵活的 bus/侧链（side-chain）布局、静音标志，以及一个把处理器与编辑器分离的、更清晰的组件模型。
2011–2018
AUv3 把沙盒化的 Audio Units 带到了 iOS 和 macOS。Avid 用 AAX（原生与 DSP/HDX）取代 RTAS，用于 Pro Tools。Roli 收购了 JUCE（2014）；如今的 plugin 世界压倒性地是软件、跨平台且基于原生 CPU 的。
2022
CLAP（CLever Audio Plugin）—— 一个来自 Bitwig 和 u-he 的开源、MIT 许可格式 —— 带来现代的线程模型、复音逐音符（per-note）调制与逐复音参数控制，迅速获得了宿主支持。同一年，浏览器的 Web Audio 与 WebAssembly 让运行于本页面的 plugin 成为现实。
plugin 对录音室所做的，正如电子表格对会计办公桌所做的：它不只是把工具数字化，更消解了工具与工作台之间的边界，使得一个无限的机架可以被随心所欲地召唤与重新排布。

2格式 —— 承载 plugin 的技术

格式（format） 是 plugin 与宿主之间的契约：二进制如何打包、宿主如何发现并实例化它、bus 与参数如何描述、process 回调如何被调用。选择支持哪些格式是第一个工程决策；大多数开发者通过一个框架同时支持多种格式。

格式所有者始于平台备注

AAXAvid2011Win / macOS仅用于 Pro Tools；有原生与 DSP（HDX）两种变体。SDK 需要 Avid 注册；要求签名构建。

在种种差异之下，每种格式都暴露同样几个概念：一种 枚举参数 的方式（带范围、单位和自动化）、一种 bus 布局（单声道/立体声/侧链的输入与输出）、一个作用于采样块的 process 回调，以及一种 保存与恢复状态 的机制，让会话能精确还原你所听到的内容。好的框架会用一个 API 隐藏掉格式相关的底层细节，于是你只写一次 DSP，就能同时编译成 VST3、AU、AAX、CLAP 和Standalone。

本网站通篇使用的 Web 对应物 —— Web Audio 的 AudioWorkletNode —— 本身也是一种“格式”：在专用音频线程上的 process 回调、以自动化曲线形式送达的参数，以及用于 GUI 的消息端口。它与 VST3/AU 的对应关系完全一致。

LFO、包络跟随器、宏控制器，路由到其他 plugin 的参数（取决于宿主）。

调音器、调性侦测器，以及驱动其他处理器的触发器。

4Plugin 的内部架构

无论格式或框架如何，一个 plugin 都有相同的四个部分。理解它们之间的边界 —— 尤其是音频线程与其余一切之间的那堵墙 —— 就是这门手艺的全部。

1 · 处理器（DSP 核心）

实时的核心。一个 processBlock 回调接收音频 buffer 和当前参数，逐采样或逐块地计算输出。不分配、不加锁、无 I/O。

2 · 参数（Parameters）

可自动化、宿主可见的控制项，每个都带有范围、单位和默认值。它们原子化地跨越线程边界，通常会被平滑处理以避免 zipper noise（拉链噪声）。

3 · 状态（State）

随会话或预设保存的完整快照：参数加上任何附加数据（加载的 IR、曲线）。作为一段不透明的二进制 blob 与宿主进行序列化往返。

4 · 编辑器（GUI）

旋钮、电平表和显示界面的可选窗口，运行在消息线程上。它观察参数并把改动发回去 —— 从不直接触碰 DSP 数据。

实时规范（The real-time contract）

音频回调在硬性期限下运行。在 48 kHz 采样率、128 采样 buffer 的情况下，宿主期望大约每 $128/48000 \approx 2.67$ ms 交付下一个数据块，永远如此，毫无例外。错过它，听者就会听到一声爆音或中断。在回调内部，以下规则是绝对的：

  • 不分配内存 —— new/malloc 可能在操作系统上阻塞。在 prepareToPlay 中预先分配好一切。
  • 不加锁 —— 被低优先级线程持有的 mutex 可能导致优先级反转和爆音。用无锁 FIFO 和原子变量通信。
  • 不调用系统调用 —— 没有文件、网络或控制台 I/O；没有无界循环。
  • 有界且确定的计算 —— 一个数据块的开销不能以可能突变的方式依赖数据。
$$t_{\text{deadline}} = \frac{N_{\text{buffer}}}{f_s} \quad\Rightarrow\quad \frac{128}{48000}\,\text{s} \approx 2.67\ \text{ms}$$

DSP 所做的一切 —— 每个 biquad、每个延迟 tap、每个振荡器 —— 都是一小笔可预测的运算量，被精心设计成即使同时运行数十个实例也能从容落在该时间窗内。

为什么参数必须被平滑处理

参数若从一块到下一块瞬间改变，会在系数或增益中产生阶跃不连续，耳朵会把它听成一声爆音（“zipper noise”）。解决办法是按采样应用一阶平滑器：

$g[n] = g[n-1] + \alpha\,(g_{\text{target}} - g[n-1])$

其中 $\alpha$ 针对较短的时间常数（几毫秒）选取。框架会以 SmoothedValue（JUCE）或 k-rate 的 AudioParam 渐变（Web Audio）形式提供这一能力。本合集中的每个示例都会平滑自己的参数。

6DSP 基础构建模块

一小套出奇精简的原语，经过组合与调校，就能产生全部的效果器与乐器目录。每一项都链接到它实际发挥作用的示例。

The sample loop（采样循环）

归根结底，这一切都是对采样的循环。处理器保留一些 状态（state）（过去的输入与输出、buffer 内容、振荡器相位），并对每个到来的采样 $x[n]$，作为输入与该状态的函数输出$y[n]$。一个线性时不变模块可以由一个 差分方程（difference equation）完整描述：

$$y[n] = \sum_{k=0}^{M} b_k\,x[n-k] \;-\; \sum_{k=1}^{N} a_k\,y[n-k]$$

其行为由传递函数 $H(z) = \dfrac{\sum_k b_k z^{-k}}{1+\sum_k a_k z^{-k}}$ 刻画，在单位圆$z=e^{j\omega}$ 上求值即可读出频率响应。滤波器、均衡器、基于 comb 的延迟和混响都源自这一关系。

Biquads & filters（双二阶与滤波器）

二阶 IIR 小节 —— 每个均衡器和合成器中谐振滤波器的原子。

Delay lines（延迟线）

带（分数）读 tap 的环形 buffer —— delay、reverb 和 modulation 的基础。

Envelopes & detectors（包络与检测器）

跟随或塑造电平随时间变化的包络跟随器与 ADSR 发生器 —— dynamics 与音符表达（articulation）的引擎。

Oscillators（振荡器）

限带发生器（PolyBLEP、波表），用于synthesis，也用作调制用的 LFO。

Nonlinearities（非线性）

添加谐波的无记忆波形塑形器 —— distortion 与 saturation 的核心，用过采样驯服。

Transforms（变换）

FFT 及其近亲把处理移到频域，用于频谱效果、卷积混响与分析。参见变换指南。

7构建与发布

plugin 既是程序也是产品。把可用的 DSP 变成能在每台机器的每个宿主中可靠加载的东西，本身就是一门学问。

  • 构建系统。 现代 JUCE 使用 CMake 生成所有目标；经典路径是 Projucer。CI 矩阵为 Windows、macOS（x86-64 + arm64 通用二进制）和 Linux 交叉编译。
  • 验证。 Apple 的 auval 把关 AU 的加载；社区版 pluginval 针对线程、状态和 bus 布局的边界情况对 VST3/AU/AAX 进行压力测试。发布前通过它们没有商量余地。
  • 代码签名与公证。 macOS 要求已签名、已公证、启用强化运行时（hardened runtime）的二进制，否则 Gatekeeper 会拦截；Windows 期望 Authenticode 签名。AAX 还额外要求 Avid 的 PACE 签名。
  • 安装程序。 plugin 位于固定目录（macOS 上为 ~/Library/Audio/Plug-Ins/…，Windows 上为 %CommonProgramFiles%\VST3）。安装程序会把每种格式的 bundle 放到正确位置，并清理旧版本。
  • 许可与保护。 从简单的序列号到挑战-响应（challenge–response）以及第三方系统；反盗版与用户好感之间永恒的两难。
  • 延迟报告。 任何 look-ahead 或过采样都会引入延迟；plugin 必须报告自己的延迟，宿主才能加以补偿并保持音轨同步。
本合集中的浏览器示例完全绕开了签名与安装程序 —— 它们只是网页 —— 但它们同样遵守已发布的原生 plugin 必须具备的 DSP 正确性、参数平滑与延迟感知。

8示例合辑

九个仓库。这个枢纽站、一份深入的 JUCE 教程，以及七个可运行的 plugin 示例 —— 每一个都是自包含的页面，带有可实时试听的演示、真实的 DSP 数学，以及等效的 JUCE C++。

探索这个家族

  • JUCE Tutorial —— 从空文件夹构建一个真实的 plugin：AudioProcessor、APVTS 参数、processBlock、编辑器与 look-and-feel、MIDI、预设、打包。
  • Parametric EQ —— RBJ biquad 菜谱、可拖拽的响应曲线、实时分析器。
  • Compressor —— 前馈动态、增益计算器、knee、增益衰减电平表。
  • Reverb —— Schroeder/Freeverb comb–allpass 网络、实测的脉冲响应。
  • Delay —— 插值延迟线、滤波反馈、乒乓、速度同步。
  • Distortion / Saturation —— 波形塑形、谐波生成、混叠与过采样。
  • Modulation —— 来自同一个扫频 LFO 的合唱、镶边与移相。
  • Synthesiser —— 带 PolyBLEP 振荡器、可演奏的复音减法乐器。
